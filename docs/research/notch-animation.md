# Notch open/close animation: how open-source notch apps make the notch itself grow

Research date: 2026-11-09. Source code was read from shallow clones at the commits linked below. DynamicNotchKit and NotchDrop are MIT; boring.notch and Atoll are GPL-3.0, so they are only described here and no code was copied. Apple guidance comes from the WWDC23 session page and the HIG JSON (`developer.apple.com/tutorials/data/design/human-interface-guidelines/live-activities.json`).

Commits: [DNK] DynamicNotchKit `cd0b3e5` (2026-02-18), [ND] NotchDrop `e70b3d7` (2026-05-19), [BN] boring.notch `b7611bb` (2026-10-31), [AT] Atoll `4a939b0` (2026-11-09).

## Summary

| | DynamicNotchKit | NotchDrop | boring.notch | Atoll |
|---|---|---|---|---|
| Open curve | `.bouncy(duration: 0.4)` | `.interactiveSpring(duration: 0.5, extraBounce: 0.25, blendDuration: 0.125)` | `.spring(response: 0.42, dampingFraction: 0.8)` (the tap wraps it in `.interactiveSpring(response: 0.38, dampingFraction: 0.8)`) | `.spring(response: 0.42, dampingFraction: 1.0)` |
| Close curve | `.smooth(duration: 0.4)`, then the window fades out over 0.15 s | same spring as open | `.spring(response: 0.45, dampingFraction: 1.0)` | `.spring(response: 0.45, dampingFraction: 1.0)` |
| What animates | mask shape's frame + corner radii | shape frame + radii (mask built with `destinationOut`) | content frame + `clipShape` radii | same as boring.notch |
| Window | fixed (half the screen), alpha fade in/out | fixed (screen width × 200), always on screen | fixed 640 × 210, always on screen | resized without animation before opening, 4 pt above the screen top |
| Closed shape vs. hardware | notch size plus 6 pt "ears", radii 6/14, 0.5 pt horizontal inset | notch **minus 4 pt** each way, radius 8: hidden *behind* the notch | notch + 4 pt wide (ears included), radii 6/14 | same as boring.notch, plus 4 pt bleed above the top edge |
| Shadow | 0 unless expanded; then 0.5 opacity, radius 10 | 0 closed; opacity 1, radius 16 open/hover | clear closed; 0.7 opacity, radius 6 open/hover | clear closed; 0.6 opacity, radius 10 open/hover |
| Content in | blur 10 + `scale(y: 0.6, anchor: .top)` + opacity, same curve as the shape | `.scale` (from 0) + opacity + `offset(y: -h/2)`, same curve | `.scale(0.8, anchor: .top)` + opacity, `.smooth(duration: 0.35)` | tabs: move + opacity; legacy: `.blurReplace` |

**All four have one thing in common.** In every closed state the black shape is the notch, or something the notch completely hides. The shadow is off whenever the panel is closed. Opening then only changes the size and corner radii of that same black shape. None of them shows a new view or window when the panel opens.

## 1. DynamicNotchKit (MrKai77)

**Curves.** For the notch style, opening is `.bouncy(duration: 0.4)`, closing is `.smooth(duration: 0.4)`, and switching between compact and expanded is `.snappy(duration: 0.4)` ([DynamicNotchStyle.swift L66-80](https://github.com/MrKai77/DynamicNotchKit/blob/cd0b3e52d537db115ad3a9d89601f20e0bee8d27/Sources/DynamicNotchKit/DynamicNotch/DynamicNotchStyle.swift#L66-L80)). Hover changes use `.snappy(duration: 0.4)` ([NotchContentView.swift L55](https://github.com/MrKai77/DynamicNotchKit/blob/cd0b3e52d537db115ad3a9d89601f20e0bee8d27/Sources/DynamicNotchKit/Views/NotchContentView.swift#L55)). The library waits 0.4 s, "the time it takes for the animation to complete" ([DynamicNotch.swift L214-216](https://github.com/MrKai77/DynamicNotchKit/blob/cd0b3e52d537db115ad3a9d89601f20e0bee8d27/Sources/DynamicNotchKit/DynamicNotch/DynamicNotch.swift#L214-L216)).

**What animates.** A full black `Rectangle` padded by −50 pt ("the opening/closing animation can overshoot, so this makes sure that it's still black") is masked by `NotchShape` ([NotchView.swift L56-77](https://github.com/MrKai77/DynamicNotchKit/blob/cd0b3e52d537db115ad3a9d89601f20e0bee8d27/Sources/DynamicNotchKit/Views/NotchView.swift#L56-L77)). The shape's `animatableData` is only the pair (top radius, bottom radius) ([NotchShape.swift L22-33](https://github.com/MrKai77/DynamicNotchKit/blob/cd0b3e52d537db115ad3a9d89601f20e0bee8d27/Sources/DynamicNotchKit/Views/NotchShape.swift#L22-L33)). Its size animates through the mask's `.frame`. When the panel is hidden, the frame is fixed at `notchSize.width + 2 * topCornerRadius` × `notchSize.height`. When it's shown, the frame is `nil`, so the mask takes the content's size. The mask is top-aligned in an infinite frame, so it grows downward from the top edge (L69-73). The mask also gets `.padding(.horizontal, 0.5)` (L68). Radii go from 6/14 (compact or hidden) to 15/20 (expanded) ([NotchView.swift L20-42](https://github.com/MrKai77/DynamicNotchKit/blob/cd0b3e52d537db115ad3a9d89601f20e0bee8d27/Sources/DynamicNotchKit/Views/NotchView.swift#L20-L42), [DynamicNotchStyle.swift L45](https://github.com/MrKai77/DynamicNotchKit/blob/cd0b3e52d537db115ad3a9d89601f20e0bee8d27/Sources/DynamicNotchKit/DynamicNotch/DynamicNotchStyle.swift#L45)).

**Window.** The window is a fixed-size borderless `NSPanel`, half the screen's width and height, hanging from the top center ([DynamicNotch.swift L350-392](https://github.com/MrKai77/DynamicNotchKit/blob/cd0b3e52d537db115ad3a9d89601f20e0bee8d27/Sources/DynamicNotchKit/DynamicNotch/DynamicNotch.swift#L350-L392)). It is at level `.screenSaver` with `hasShadow = false` and a clear background ([DynamicNotchPanel.swift L23-26](https://github.com/MrKai77/DynamicNotchKit/blob/cd0b3e52d537db115ad3a9d89601f20e0bee8d27/Sources/DynamicNotchKit/Utility/DynamicNotchPanel.swift#L23-L26)). Only SwiftUI content animates inside it.

**Matching the notch.** `notchSize` is `frame.width − auxiliaryTopLeftArea.width − auxiliaryTopRightArea.width` × `safeAreaInsets.top` ([NSScreen+Extensions.swift L23-34](https://github.com/MrKai77/DynamicNotchKit/blob/cd0b3e52d537db115ad3a9d89601f20e0bee8d27/Sources/DynamicNotchKit/Utility/NSScreen+Extensions.swift#L23-L34)). The hidden mask is exactly that size plus the outward top fillets. That makes the start of the open, and the end of the close, the notch's own outline.

**Hiding the seams.**
- Open: the window is created without being ordered front. `withAnimation(opening) { state = .expanded }` runs first, and only then is the window shown, with the comment "Start animation BEFORE showing window — this eliminates stutter". The window then fades its alpha from 0 to 1 over 0.15 s with ease-out, "to hide any initial frame glitches" ([DynamicNotch.swift L184-194, L395-408](https://github.com/MrKai77/DynamicNotchKit/blob/cd0b3e52d537db115ad3a9d89601f20e0bee8d27/Sources/DynamicNotchKit/DynamicNotch/DynamicNotch.swift#L184-L194)).
- Close: `withAnimation(closing) { state = .hidden }`. After 0.25 s ("wait for most of animation"), the window fades its alpha to 0 over 0.15 s with ease-in, "to hide any closing glitches". Only then is it closed ([DynamicNotch.swift L298-331](https://github.com/MrKai77/DynamicNotchKit/blob/cd0b3e52d537db115ad3a9d89601f20e0bee8d27/Sources/DynamicNotchKit/DynamicNotch/DynamicNotch.swift#L298-L331)).
- Switching between compact and expanded first collapses to hidden, waits 0.25 s, then expands, unless `skipIntermediateHides` is set (L196-211).

**Content.** Expanded content is inserted only in `.expanded`. Its transition is `.blur(intensity: 10)` + `.scale(y: 0.6, anchor: .top)` + `.opacity`. It runs on the same animation as the shape, with no delay ([NotchView.swift L141-153](https://github.com/MrKai77/DynamicNotchKit/blob/cd0b3e52d537db115ad3a9d89601f20e0bee8d27/Sources/DynamicNotchKit/Views/NotchView.swift#L141-L153); the transitions are defined in [BlurModifier.swift](https://github.com/MrKai77/DynamicNotchKit/blob/cd0b3e52d537db115ad3a9d89601f20e0bee8d27/Sources/DynamicNotchKit/Utility/BlurModifier.swift)). While the panel isn't expanded, the content's frame is clamped to `maxWidth/maxHeight: 0` (L89-95). Content sits below a top safe-area inset as tall as the notch, with 15 pt insets on the sides and bottom. Compact side content uses blur 10 + `scale(x: 0)` anchored toward the notch + opacity (L112, L125).

**Shadow.** Applied to the whole ZStack: opacity 0 unless expanded (0.5; 0.8 when hovering with `.increaseShadow`), and radius 0 when hidden, otherwise 10 or 20 ([NotchContentView.swift L20-52](https://github.com/MrKai77/DynamicNotchKit/blob/cd0b3e52d537db115ad3a9d89601f20e0bee8d27/Sources/DynamicNotchKit/Views/NotchContentView.swift#L20-L52)). The shadow changes on the same state animation, so it fades in as the panel grows and fades out as it shrinks.

## 2. NotchDrop (Lakr233)

**Curve.** Open and close use the same curve: `.interactiveSpring(duration: 0.5, extraBounce: 0.25, blendDuration: 0.125)` ([NotchViewModel.swift L21-25](https://github.com/Lakr233/NotchDrop/blob/e70b3d715a99e47de6eb823540282eafc7401a3a/NotchDrop/NotchViewModel.swift#L21-L25)). It is applied with `.animation(vm.animation, value: vm.status)` ([NotchView.swift L70](https://github.com/Lakr233/NotchDrop/blob/e70b3d715a99e47de6eb823540282eafc7401a3a/NotchDrop/NotchView.swift#L70)).

**Three sizes** ([NotchView.swift L15-41](https://github.com/Lakr233/NotchDrop/blob/e70b3d715a99e47de6eb823540282eafc7401a3a/NotchDrop/NotchView.swift#L15-L41)):
- closed: hardware notch **− 4 pt in width and height**, radius 8
- popping (hover): notch width, height **+ 4 pt**, radius 10, so a sliver peeks below the notch as a hint
- opened: 600 × 160, radius 32

So the closed shape is smaller than the hardware notch and fully hidden behind it. There is no seam to align. Popping is a 4 pt "the notch is alive" step before the full open ([NotchViewModel+Events.swift L56-64](https://github.com/Lakr233/NotchDrop/blob/e70b3d715a99e47de6eb823540282eafc7401a3a/NotchDrop/NotchViewModel+Events.swift#L56-L64)).

**Shape.** A black `Rectangle` masked by a group: a bottom-rounded rect, plus two outward top fillets cut with `.blendMode(.destinationOut)` inside `.compositingGroup()`, offset by ±0.5 pt to overlap ([NotchView.swift L75-136](https://github.com/Lakr233/NotchDrop/blob/e70b3d715a99e47de6eb823540282eafc7401a3a/NotchDrop/NotchView.swift#L75-L136)). The frame is `(width + 2 * radius) × height`. Size and radius animate through the frame and `clipShape(.rect(...))`. There is no custom `animatableData`.

**Window.** The window is fixed at the screen's full width × 200 pt at the top, always ordered front, at level `.statusBar + 8` ("kills ibar"), with `hasShadow = false` ([NotchWindow.swift L24-37](https://github.com/Lakr233/NotchDrop/blob/e70b3d715a99e47de6eb823540282eafc7401a3a/NotchDrop/NotchWindow.swift#L24-L37), [NotchWindowController.swift L10, L49-67](https://github.com/Lakr233/NotchDrop/blob/e70b3d715a99e47de6eb823540282eafc7401a3a/NotchDrop/NotchWindowController.swift#L49-L67)). Because the notch shape is always drawn, there's no window show/hide to hide. Half a second after closing, the shape drops to opacity 0.3, still behind the hardware notch ([Events L95-104](https://github.com/Lakr233/NotchDrop/blob/e70b3d715a99e47de6eb823540282eafc7401a3a/NotchDrop/NotchViewModel+Events.swift#L95-L104), [NotchView.swift L48](https://github.com/Lakr233/NotchDrop/blob/e70b3d715a99e47de6eb823540282eafc7401a3a/NotchDrop/NotchView.swift#L48)).

**Notch size.** Width from `auxiliaryTopLeftArea`/`auxiliaryTopRightArea` and height from `safeAreaInsets.top` ([Ext+NSScreen.swift L11-20](https://github.com/Lakr233/NotchDrop/blob/e70b3d715a99e47de6eb823540282eafc7401a3a/NotchDrop/Ext+NSScreen.swift#L11-L20)).

**Content.** Inserted only when `.opened`, with `.scale` (SwiftUI default: from 0) + `.opacity` + `.offset(y: -openedHeight/2)`, on the same spring ([NotchView.swift L49-67](https://github.com/Lakr233/NotchDrop/blob/e70b3d715a99e47de6eb823540282eafc7401a3a/NotchDrop/NotchView.swift#L49-L67)). The content starts collapsed at the notch and travels down with the shape. On close it shrinks back up into the notch.

**Shadow.** Opacity 1, radius 16, only when opened or popping; 0 when closed. It animates with the status ([NotchView.swift L83-86](https://github.com/Lakr233/NotchDrop/blob/e70b3d715a99e47de6eb823540282eafc7401a3a/NotchDrop/NotchView.swift#L83-L86)).

## 3. boring.notch (TheBoredTeam), GPL: described only

**Curves.** There are separate curves by direction: open `spring(response: 0.42, dampingFraction: 0.8)`, close `spring(response: 0.45, dampingFraction: 1.0)` (critically damped, no overshoot). The view picks one from `notchState` and attaches it with `.animation(_, value: notchState)` ([ContentView.swift L120-129](https://github.com/TheBoredTeam/boring.notch/blob/b7611bbf32c627a3427408fc142486900d71a23f/boringNotch/ContentView.swift#L120-L129)). Taps and hovers also wrap `vm.open()` in a shared `interactiveSpring(response: 0.38, dampingFraction: 0.8)`, commented as avoiding conflicting animations (L40-41, L505-509).

**What animates.** The layout's horizontal padding (closed: the bottom radius; open: the top radius + 12) and its height (`openNotchSize.height` when open, the content's height when closed) animate. On top of that, a `.background(.black)` is cut by `.clipShape(NotchShape)`, a copy of DynamicNotchKit's shape with animatable radii ([ContentView.swift L91-121](https://github.com/TheBoredTeam/boring.notch/blob/b7611bbf32c627a3427408fc142486900d71a23f/boringNotch/ContentView.swift#L91-L121), [NotchShape.swift](https://github.com/TheBoredTeam/boring.notch/blob/b7611bbf32c627a3427408fc142486900d71a23f/boringNotch/components/Notch/NotchShape.swift)). Radii go from 6/14 closed to 19/24 open, and the open size is 640 × 190 ([sizing/matters.swift L15-18](https://github.com/TheBoredTeam/boring.notch/blob/b7611bbf32c627a3427408fc142486900d71a23f/boringNotch/sizing/matters.swift#L15-L18)).

**Top seam.** A 1 pt black `Rectangle` overlay at the top, inset by the top radius, covers anti-aliasing along the screen edge ([ContentView.swift L105-110](https://github.com/TheBoredTeam/boring.notch/blob/b7611bbf32c627a3427408fc142486900d71a23f/boringNotch/ContentView.swift#L105-L110)).

**Matching the notch.** The closed width is `screen.width − auxLeft − auxRight + 4`. The height is `safeAreaInsets.top` in "match real notch" mode, otherwise the menu bar height or a user value ([sizing/matters.swift L39-77](https://github.com/TheBoredTeam/boring.notch/blob/b7611bbf32c627a3427408fc142486900d71a23f/boringNotch/sizing/matters.swift#L39-L77)). In the plain closed state, the content is a clear rectangle `closedWidth − 20` wide ([ContentView.swift L299-300](https://github.com/TheBoredTeam/boring.notch/blob/b7611bbf32c627a3427408fc142486900d71a23f/boringNotch/ContentView.swift#L299-L300)) with 14 pt padding on each side. My arithmetic: that makes the outer width ≈ hardware + 12, and the body between the 6 pt fillets ≈ the hardware width.

**Window.** The window is a fixed `NSPanel` of 640 × (190 + 20 shadow padding), top-centered and always ordered front ([boringNotchApp.swift L234-280](https://github.com/TheBoredTeam/boring.notch/blob/b7611bbf32c627a3427408fc142486900d71a23f/boringNotch/boringNotchApp.swift#L234-L280)). It's at level `.mainMenu + 3` with no window shadow, and is not key ([BoringNotchWindow.swift L24-48](https://github.com/TheBoredTeam/boring.notch/blob/b7611bbf32c627a3427408fc142486900d71a23f/boringNotch/components/Notch/BoringNotchWindow.swift#L24-L48)). The root view has `.compositingGroup()` and then `scaleEffect(anchor: .top)`, used for the pull-to-open gesture ([ContentView.swift L205-213](https://github.com/TheBoredTeam/boring.notch/blob/b7611bbf32c627a3427408fc142486900d71a23f/boringNotch/ContentView.swift#L205-L213)).

**Content.** The open view (home/shelf) appears only when open, with `.scale(scale: 0.8, anchor: .top).combined(with: .opacity)` on its own `.smooth(duration: 0.35)` ([ContentView.swift L345-358](https://github.com/TheBoredTeam/boring.notch/blob/b7611bbf32c627a3427408fc142486900d71a23f/boringNotch/ContentView.swift#L345-L358)). The header replaces the closed placeholder with the default (opacity) transition (L295-298).

**Shadow.** `.black.opacity(0.7)` at radius 6 (or 4) only when open or hovering, otherwise `.clear`, so it rides the state spring ([ContentView.swift L111-114](https://github.com/TheBoredTeam/boring.notch/blob/b7611bbf32c627a3427408fc142486900d71a23f/boringNotch/ContentView.swift#L111-L114)).

## 4. Atoll (Ebullioscopic, boring.notch fork), GPL: described only

- **Curves:** open `spring(response: 0.42, dampingFraction: 1.0)`, close `spring(response: 0.45, dampingFraction: 1.0)`. Both are critically damped, so the growth doesn't bounce; hover uses `.bouncy.speed(1.2)`. The legacy path uses one spring plus `.blurReplace` ([ContentView.swift L691-711](https://github.com/Ebullioscopic/Atoll/blob/4a939b0fdb247b75c4a4c19f14e5fe2d57dbbb65/DynamicIsland/ContentView.swift#L691-L711)). The modern path is the default ([Constants.swift L1030](https://github.com/Ebullioscopic/Atoll/blob/4a939b0fdb247b75c4a4c19f14e5fe2d57dbbb65/DynamicIsland/models/Constants.swift#L1030)).
- **Top bleed:** `notchTopScreenBleedAmount = 4` ([sizing/matters.swift L362-367](https://github.com/Ebullioscopic/Atoll/blob/4a939b0fdb247b75c4a4c19f14e5fe2d57dbbb65/DynamicIsland/sizing/matters.swift#L362-L367)). The window is placed 4 pt above `screen.maxY`, with pixel-rounded frames ([DynamicIslandApp.swift L440-459, L670-680](https://github.com/Ebullioscopic/Atoll/blob/4a939b0fdb247b75c4a4c19f14e5fe2d57dbbb65/DynamicIsland/DynamicIslandApp.swift#L440-L459)). The clipped shape is padded down 4 pt and a 4 pt black strip fills the gap, "so the notch's top corners [stay] anchored to the visible screen edge" ([ContentView.swift L663-675](https://github.com/Ebullioscopic/Atoll/blob/4a939b0fdb247b75c4a4c19f14e5fe2d57dbbb65/DynamicIsland/ContentView.swift#L663-L675)). The shape's top edge is never drawn on screen.
- **Shadow:** `.compositingGroup()` and then `.shadow(.black.opacity(0.6), radius 10 or 5)`, only when open or hovering (L676-682).
- **Window:** `open()` resizes the window to the open size *without animation* before setting the state, and skips a no-op `setFrame` to avoid an AppKit display transaction ([DynamicIslandViewModel.swift L395-419](https://github.com/Ebullioscopic/Atoll/blob/4a939b0fdb247b75c4a4c19f14e5fe2d57dbbb65/DynamicIsland/models/DynamicIslandViewModel.swift#L395-L419), [DynamicIslandApp.swift L681-684](https://github.com/Ebullioscopic/Atoll/blob/4a939b0fdb247b75c4a4c19f14e5fe2d57dbbb65/DynamicIsland/DynamicIslandApp.swift#L681-L684)).
- Radii and closed sizing are the same as boring.notch: 6/14 → 19/24 ([sizing/matters.swift L199](https://github.com/Ebullioscopic/Atoll/blob/4a939b0fdb247b75c4a4c19f14e5fe2d57dbbb65/DynamicIsland/sizing/matters.swift#L199)).

## 5. Apple guidance

- WWDC23 "Design dynamic Live Activities": the Dynamic Island "is designed to feel like a living organism, with a deliberate elasticity that serves as a playful contrast to the fixed nature of the hardware it embodies". It "can organically shape shift". It can "grow horizontally" to compact and "bloom into a larger Expanded view". Content should be "concentric with its shape". The session publishes no spring numbers. ([developer.apple.com/videos/play/wwdc2023/10194](https://developer.apple.com/videos/play/wwdc2023/10194/))
- HIG Live Activities: the Dynamic Island uses "a black opaque background". "The expanded presentation is an enlarged version of the compact or minimal presentation. Ensure information and layouts expand predictably." When layouts change, "preserve as much of the existing layout as possible by animating existing elements to their new positions rather than removing and animating them back in." ([HIG Live Activities](https://developer.apple.com/design/human-interface-guidelines/live-activities))

## 6. Compared with Topstash today

Topstash already uses the shared core: a fixed window, an oversized black backing masked by an animatable `NotchShape` (size + radii), closed radii 6/14, and content in with blur and a top-anchored scale. The differences that matter for "the notch grows":

- **The shadow is always on.** `PanelView.backing` draws `.shadow(opacity 0.45, radius 12, y 6)` in every mode (`Topstash/Views/PanelView.swift` L57-61). So the notch-sized shape casts a shadow below the hardware notch in the first and last frames. All four apps turn the shadow off (opacity 0 or `.clear`) when closed and let it ride the state animation.
- **The closed shape is exactly the hardware rect** (`NotchPanelController.place`, `panel.closedSize = area.rect.size`), with no top bleed or seam cover. The others either hide it behind the notch (ND: −4 pt), cover the top edge (BN: a 1 pt black strip; AT: 4 pt above the screen), or inset the mask by 0.5 pt (DNK).
- **Content scale is subtle** (0.96, after a 0.07 s delay). Others use 0.6 (y only), 0.8, or 0 + offset, all anchored at the top, so content visibly comes *out of* the notch with the shape.
- **Curves are in the same range.** Open: `.snappy(0.4)` (bounce about 0.15), against `.bouncy(0.4)`, `spring(0.42, 0.8)`, or `spring(0.42, 1.0)`. Close: `.smooth(0.3)`, against `.smooth(0.4)` and `spring(0.45, 1.0)`. No overshoot when closing, everywhere.
- **Window level:** ours is `.statusBar`. The others are higher (`.statusBar + 8`, `.mainMenu + 3`, `.screenSaver`).

## Techniques worth adopting (by likely impact)

1. **Shadow only while open.** Shadow opacity 0 (and radius 0) when closed, animated by the same open/close curve as the shape. DNK uses 0.5/r10, BN 0.7/r6, AT 0.6/r10, ND 1.0/r16. This removes the most visible "separate object under the notch" cue at the start of the open and the end of the close.
2. **Make the closed shape vanish into the notch and hide the top edge.** Either draw the closed shape slightly *inside* the hardware notch (ND: −4 pt width/height), or bleed the black above the screen top (AT: window 4 pt above `maxY` plus a 4 pt black strip; BN: a 1 pt black overlay across the top, inset by the top radius). Round the window frame to whole pixels (AT).
3. **Content grows out of the top with the shape.** Use a stronger top-anchored scale: `scale(y: 0.6, anchor: .top)` + blur 10 + opacity on the shape's own curve (DNK), or `.scale(0.8, anchor: .top)` + opacity with `.smooth(0.35)` (BN). Keep fading content out *before* the shape collapses (ours already does).
4. **A critically damped close.** `spring(response: 0.45, dampingFraction: 1.0)` (BN/AT) or `.smooth(0.4)` (DNK). Let it fully settle before `orderOut`. DNK adds a 0.15 s ease-in window alpha fade starting at 0.25 s to mask the last frames.
5. **Start the state change before ordering the window in** (DNK), and optionally fade window alpha 0 → 1 over 0.15 s with ease-out, so the first composited frame is never a stale layout.
6. **Optional hover "pop"** (ND): grow the closed shape 4 pt taller on hover, with the same spring and the shadow on, so the open reads as the notch continuing to grow.
7. **Hygiene:** an oversized black backing for spring overshoot (DNK −50 pt; ours already does this), `.compositingGroup()` before `.shadow` (AT), and a window level above the menu bar (`.mainMenu + 3` or `.statusBar + 8`).
